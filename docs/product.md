# 제품 기획

## 비전

AI를 활용해 기획, 디자인, 개발, 인프라와 운영을 하나의 저장소에서 반복 가능하게 수행한다. 첫 제품은 방문자가 배포 환경을 확인할 수 있는 작은 Next.js 웹 앱이다. 핵심 성과는 복잡한 서비스 기능보다 PR에서 인프라 변경을 검토하고 두 환경에 재현성 있게 배포하는 것이다.

## 사용자와 주요 흐름

| 사용자 | 원하는 일 | 완료 기준 |
| --- | --- | --- |
| 방문자 | HTTPS로 앱 열기 | 페이지 로드와 `/api/health` 응답 |
| 개발자 | 로컬에서 기능 개발 | `pnpm dev`, 타입 검사, 빌드 가능 |
| 리뷰어 | PR의 앱·인프라 영향 파악 | 빌드, fmt, validate, 환경별 plan 확인 |
| 운영자 | preprod 확인 후 prod 승격 | merge 후 preprod, 승인 후 prod 배포 및 롤백 가능 |

## 초기 커밋 범위

- 실행 가능한 Next.js 앱, Node.js 22, pnpm workspaces, health API.
- `AGENTS.md`, 기획·디자인·아키텍처·운영 문서와 앱 CI.

## 후속 구현 범위

- Terraform의 VPC, 공개·비공개 서브넷, 보안 그룹, ECR, ECS on EC2, ALB, ACM HTTPS, Route 53 DNS, S3 비공개 버킷, Lambda 예제.
- `preprod`/`prod` state와 리소스 분리. PR 검증과 GitHub OIDC 기반 배포.
- 비용이 큰 공개 경로를 스위치로 관리하고, 운영 문서에 생성·종료 절차를 기록.

## 현 단계 범위 밖

인증, 사용자 데이터베이스, 업로드 UI, CI에서 Lambda 함수 URL 공개, 멀티 리전 고가용성, 자동 비용 보증은 다음 단계로 남긴다. private subnet은 네트워크 경계를 학습하기 위해 생성하지만 NAT가 없어 현재 워크로드를 배치하지 않는다.

## 성공 조건

1. 로컬에서 앱을 실행하고 health 응답을 받는다.
2. PR에서 앱 빌드·Terraform 정적 검사와 두 환경의 plan을 확인한다.
3. merge 후 preprod에서 새 이미지를 HTTPS로 제공한다.
4. 승인된 prod 수동 실행으로 같은 커밋을 배포한다.
5. 운영자가 비용과 리소스를 보고 공개 서비스를 꺼서 비용을 줄일 수 있다.

## 다음 결정

- 앱이 실제 데이터를 다루기 시작하면 데이터 모델, 저장소, 접근 제어, 개인정보 범위를 먼저 정의한다.
- 두 개 이상의 앱·공유 패키지가 생기고 빌드 시간 문제가 확인되면 Turborepo를 도입한다. 현재 pnpm workspace 구조는 그대로 유지할 수 있다.
- 지속 운영 전에는 preprod/prod를 별도 AWS 계정으로 분리하고 배포 IAM 권한을 축소한다.
